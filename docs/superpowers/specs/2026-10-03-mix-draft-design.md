# Миксы: драфт капитанами из общего лобби

Дата: 2026-10-03
Статус: согласовано, ждёт плана реализации

## Зачем

Сейчас лобби держит 10 мест (остальные — в резерве, откуда в игру не попасть),
`/create_mix` собирает одну нерейтинговую группу из 2–10 человек, а
`/create_match` и `/balance` — одну игру на всё лобби. На миксах же играют
десятки людей одновременно, несколькими играми 5×5, и составы набирают
капитаны, а не бот по MMR.

## Что получится

- Лобби вмещает до 100 игроков.
- `/create_mix` создаёт драфт **одной** игры 5×5: судья назначает двух
  капитанов. Нужно несколько игр — судья вызывает команду несколько раз;
  драфты идут параллельно и берут игроков из одного общего лобби.
- Капитаны выбирают игроков по очереди A, B, A, B…; кто ходит первым —
  жребий. Каждый капитан набирает 4 игроков (итого 5 с капитаном).
- Закончившийся драфт становится обычным рейтинговым матчем: кнопки WIN у
  судьи, ветка для скриншота, ставки в Telegram, MMR и ранги после закрытия.
- Ребаланса по MMR нет.

## Поток

1. Игроки жмут «Войти в лобби» (как сейчас).
2. Судья: `/create_mix` → скрытое поле выбора пользователей (Discord
   UserSelect, с поиском, без лимита в 25 вариантов) → два капитана.
3. Бот проверяет капитанов, убирает их из лобби, бросает жребий и публикует
   в канале **сообщение драфта**: составы, чей ход, поле «Выбрать игрока»
   (UserSelect), кнопки «Свободные игроки» и «Отменить драфт».
4. Капитан, чей ход, выбирает игрока. Бот атомарно переносит игрока из лобби в
   его команду, передаёт ход и обновляет сообщение драфта на месте.
5. После восьмого выбора сообщение драфта превращается в карточку матча
   (embed + кнопки WIN), дальше — существующий путь `publishCreatedMatch`:
   ветка от карточки с сохранением `thread_id`, окно ставок, уведомление в
   Telegram.
6. После игры игроки жмут «Встать в очередь лобби» на карточке результата
   (кнопка уже есть) и возвращаются в общий пул.

## Компоненты

### Лобби (`internal/application/lobby_service.go`)

- `lobbyCapacity`: 10 → 100. Механика резерва остаётся как защита от
  переполнения.
- Тексты лобби (`FormatPlayerList`) не должны выходить за лимит описания
  embed в Discord (4096 символов) — список обрезается с пометкой.

### Драфт (`internal/application`, новый файл `mix_draft.go`)

Состояние драфтов живёт в `LobbyService` под тем же `l.mu`, что и очередь, —
это и даёт атомарность: два драфта не могут взять одного игрока.

```go
type draft struct {
    id               int
    captains         [2]lobbyEntry   // [0] — команда A, [1] — команда B
    teams            [2][]lobbyEntry // выбранные игроки без капитанов
    turn             int             // 0 или 1 — чей ход
}
```

Методы `LobbyService`:

- `StartDraft(capA, capB string) (DraftView, error)` — аргументы — Discord ID.
  Ошибки: капитаны совпадают; капитан не в основном составе лобби. Убирает
  обоих из лобби (через `removePlayerLocked`, резерв подтягивается как
  обычно), выбирает первого ходящего случайно, выдаёт новый номер драфта.
- `PickPlayer(draftID int, pickerDiscordID, targetDiscordID string) (DraftView, error)`
  — ошибки: драфт не найден; выбирает не капитан этого драфта; сейчас не его
  ход; цель не в основном составе лобби. Переносит цель в команду, передаёт
  ход. `DraftView.Complete == true` после 8-го выбора; завершённый драфт
  остаётся в памяти и отвергает новые выборы, пока его не закроют
  `FinishDraft` или `CancelDraft`.
- `FinishDraft(draftID int) error` — удаляет завершённый драфт после того,
  как матч создан.
- `CancelDraft(draftID int) (DraftView, error)` — возвращает капитанов и
  выбранных в конец основного состава (с сохранёнными `lobbyEntry`), удаляет
  драфт. Работает и для завершённого драфта (если матч создать не удалось).

Кнопка «Свободные игроки» использует существующий `GetActivePlayers`.

`DraftView` — снимок для отрисовки: номер, капитаны, составы (имена и ID),
чей ход, `Complete`. Ошибки — сентинели в `internal/domain`
(`ErrDraftNotFound`, `ErrNotYourTurn`, `ErrNotCaptain`, `ErrNotInLobby`,
`ErrSameCaptain`), тексты для игроков формирует delivery-слой, как
`joinMessage`.

Игроки сопоставляются по Discord ID из `lobbyEntry.discordID`: при входе в
лобби бот уже привязал их к профилю, лишних запросов в БД нет.

Состояние только в памяти, как и само лобби: рестарт теряет и лобби, и
драфты, состояние остаётся согласованным.

### Discord (`internal/delivery/discord`, новый файл `mix_draft_handlers.go`)

- `/create_mix` (только судья/админ) → скрытый ответ с UserSelect
  (`min=max=2`, custom ID `mix_captains`).
- Обработчик `mix_captains`: guard + `requireReferee` → `StartDraft` →
  публичный ответ с сообщением драфта.
- Сообщение драфта: embed (Команда A / Команда B / ход) и компоненты с
  номером драфта в custom ID:
  - `mix_pick_<id>` — UserSelect `min=max=1`, «Выбрать игрока»;
  - `mix_free_<id>` — кнопка «Свободные игроки» → скрытый список лобби;
  - `mix_cancel_<id>` — кнопка «Отменить драфт», только судья.
- `mix_pick_<id>`: guard (без `requireReferee` — выбирают капитаны) →
  `PickPlayer` → `InteractionResponseUpdateMessage` с новым embed. При ошибке
  — скрытый ответ с причиной, сообщение не меняется.
- На последнем выборе: `CreateMatch` (капитан A — `captain_a_id`) → ответ
  `UpdateMessage`, превращающий сообщение драфта в карточку матча →
  ветка/ставки/Telegram. `publishCreatedMatch` получает параметр типа ответа
  (новое сообщение для `/balance`, обновление для драфта); `openMatchThread`
  берёт карточку через `InteractionResponse(i)` в обоих случаях.
- После успешного `CreateMatch` — `FinishDraft`. Если `CreateMatch` упал —
  `CancelDraft` (все возвращаются в лобби), выбравшему — скрытое сообщение об
  ошибке, сообщение драфта помечается отменённым.
- Кнопки драфта, которого нет (рестарт): «Драфт не найден — бот
  перезапускался, создайте игру заново».

### Пограничные случаи

- `/lobby_clear`, `/lobby_kick` не трогают драфты — их игроков в лобби уже нет.
- Капитан пропал — судья отменяет драфт; таймеров нет.
- Инактив-свипер лобби не видит игроков в драфтах (их нет в очереди).
- Один и тот же человек не может быть в двух драфтах: при старте и выборе он
  должен быть в лобби, а оттуда его убирает первый драфт.
